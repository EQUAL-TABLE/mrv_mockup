\### 기능별 상세



\#### ① Layout 사전분할 — LayoutLMv3 기반 KOR-Receipt Head



\- \*\*위치\*\*: OCR 파이프라인 최전단, 문서 업로드 직후

\- \*\*역할\*\*: 업로드된 이미지에서 텍스트·표·바코드 영역을 분류 → 후속 OCR 엔진에 영역별로 전달

\- \*\*적용 문서\*\*: 전력·가스 고지서, 세금계산서, B/L, AWB 등 MRV 트랙 전 증빙 문서

\- \*\*핵심 이유\*\*: 한국형 비정형 고지서는 레이아웃이 제각각 → 범용 OCR 직접 적용 시 정확도 저하. 영역 사전 분류로 94.6% 이상 필드 인식 정확도 목표 달성 기반



\---



\#### ② Dual-Head OCR — Conformer + CRNN + Late Fusion



\- \*\*위치\*\*: Layout 분할 직후, 영역별 텍스트 추출 단계

\- \*\*역할\*\*:

&#x20; - Conformer → 문맥성 텍스트(상호명, 품목명 등) 인식

&#x20; - CRNN → 숫자·특수기호(사용량, 금액, 날짜 등) 인식

&#x20; - Late Fusion → 두 엔진 결과 결합, 구조화 텍스트 출력

\- \*\*적용 대상\*\*: 전 증빙 문서 (MRV 트랙 한정)

\- \*\*핵심 이유\*\*: 문맥 정확성과 숫자 정확성을 단일 엔진으로 동시 달성 불가 → 특화 엔진 분리 후 후반 융합



\---



\#### ③ Noise 보정 — TPS + De-Shadow CNN



\- \*\*위치\*\*: OCR 전처리 단계 (①②와 병렬 또는 선행)

\- \*\*역할\*\*:

&#x20; - TPS(Thin-Plate Spline): 구겨지거나 휘어진 문서 비선형 보정 → 반듯한 이미지로 변환

&#x20; - De-Shadow CNN: 그림자·조명 불균일 보정 → 가독성 향상

\- \*\*적용 대상\*\*: 스마트폰 촬영 영수증, 구겨진 고지서 등 저품질 문서

\- \*\*핵심 이유\*\*: 로스터리 현장에서 실제 제출되는 문서 품질 편차 큼 → 보정 없으면 OCR 인식률 급락



\---



\#### ④ Key-Value 추출 — SPADE + 규칙 사전 스코어링



\- \*\*위치\*\*: OCR 완료 후, 정규화 엔진 직전

\- \*\*역할\*\*:

&#x20; - 1단계(SPADE): 이미지 전체 공간 분석 → 키·값 후보 쌍 생성

&#x20; - 2단계(규칙 사전): 한국 영수증 규칙 기반 점수 산정 → 최종 키-값 확정

&#x20; - 수식: `Score = templateMatch × 0.7 + positionMatch × 0.3`

\- \*\*출력\*\*: 날짜, 사업자번호, 품목, 사용량, 금액 등 구조화 필드

\- \*\*핵심 이유\*\*: OCR이 문자를 인식해도 "어떤 값이 어떤 필드인지" 매핑이 별도 필요 → SPADE가 위치 관계 파악, 규칙이 신뢰도 확정



\---



\#### ⑤ 다국어/단위 정규화 엔진



\- \*\*위치\*\*: KV 추출 직후, EF-Matcher 직전 (OCR Post-Processing)

\- \*\*역할\*\*:

&#x20; - 언어·통화 판별: FastText + 통화기호 규칙 병렬 실행 → 원화 환산

&#x20; - 단위 변환: 80+ 단위 → 표준 단위(kWh, kg, t·km) 자동 환산

&#x20; - 품목 시맨틱 분류: Gazetteer + Korean-BERT → NAICS/KSIC/HS 코드 매핑

&#x20; - 테이블 복원·검산: 구조 복원 + `공급가액 + 부가세 = 합계` 자동 검증

\- \*\*적용 범위\*\*: 해외 생두 인보이스(외화·외국어), 국내 전력·가스·수도 고지서 전체

\- \*\*핵심 이유\*\*: 다양한 증빙 출처에서 ISO 14064/67·IPCC·KEITI 스키마로 통일 → EF 매칭 정확도의 전제 조건



\---



\#### ⑥ EF-Matcher — Dual-Stage Matching + Hierarchical EF Graph



\- \*\*위치\*\*: 정규화 완료 후, 배출량 산정 엔진 직전

\- \*\*역할\*\*:

&#x20; - Hierarchical EF Graph(Neo4j): 연도·국가·방법론·버전·단위 계층 구조 → 검색 범위 최적화

&#x20; - 1단계(Rule-Based Filter): 연도·국가·단위 조건으로 전체 EF의 99% 가지치기

&#x20; - 2단계(Embedding Similarity): BGE-Ko/S-BERT 기반 의미 유사도로 최종 매칭

&#x20; - 혼합계수 처리: 복합 요금 항목 분해 후 가중합산

&#x20; - 결측치 보정: 베이지안 추론 + Monte Carlo → 95% CI 산출

\- \*\*출력\*\*: 각 활동자료에 대한 EF 자동 지정 + 매칭 근거 로그

\- \*\*적용 표준\*\*: IPCC 2006, KEITI 환경성적표지, PAS 2050 동시 지원

\- \*\*핵심 이유\*\*: EF 선택이 사람마다 달라 산정 결과 불일치 → 자동·일관된 매칭으로 87% 이상 정확도 목표



\---



\#### ⑦ 해시체인 감사 로그



\- \*\*위치\*\*: 파이프라인 전 단계에 걸쳐 상시 동작 (횡단 관심사)

\- \*\*역할\*\*:

&#x20; - 수식: `Hn = SHA256(Datan ‖ Hn-1)`

&#x20; - 입력 → 정규화 → EF 선택 → 배출량 산정 각 단계마다 디지털 지문 생성·연결

&#x20; - 필드 단위 원본 좌표·캡처 이미지·변환 이력 저장

&#x20; - OCR 수동 수정 시에도 수정 전/후 값, 편집자, 타임스탬프 기록 후 잠금

\- \*\*적용 범위\*\*: MRV 트랙 전용 (계산기 트랙은 문서 발급 불가이므로 해당 없음)

\- \*\*핵심 이유\*\*: 환경부/KEITI 인증 및 제3자 검증(KTL/KTR/KMR) 대응 → 위변조 불가 감사 추적성이 MRV 인증의 법적 요건
