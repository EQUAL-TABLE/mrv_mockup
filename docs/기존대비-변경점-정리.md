# MRV 프론트엔드 — 목업 vs 기존 주요 변경점 정리

> 대상: 개발팀
> 범위: 디자인/컬러 제외, **화면 흐름·기능 구조**의 큰 차이 중심
> 비교 대상
> - 목업: `mrv_front_mockup` (개선 방향 제안본)
> - 기존: `mrv-frontend` (현행 개발본)

---

## 0. 한눈에 보기

| 구분 | 기존 (mrv-frontend) | 목업 (제안) |
|---|---|---|
| 로그인 후 첫 화면 | 프로젝트 목록만 (허브) | **시스템 설명 + 방식 안내 + 프로젝트 목록** |
| 서비스/개념 안내 페이지 | 없음 | **`/guide` 서비스 안내 페이지 신설** (LCA 개념·전과정 흐름 학습) |
| 신규 프로젝트 시작 | 목록에서 즉시 생성 → 바로 기본정보 (기본값 고정) | **3단계 시작 위저드** (방식→방법론→범위 선택) |
| 진행 단계 시각화 | 좌측 세로 사이드바 메뉴만 | **작업화면 상단 가로 스텝(공정흐름) 네비 추가** |
| 각 단계 상단 안내 | 없음 (상단바 제목 한 줄뿐) | **단계마다 상단에 "목적/입력정보/얻는결과" 설명 카드** |
| 프로젝트 목록 카드 | 1열 리스트, 메타 배지 | **그리드 카드 + 상태별 진행률/결과/CTA 차별화** |
| 용어 | 전문 용어 위주 | **쉬운 용어 + 설명 병기** |

두 레포 모두 React 19 + Vite + TS + react-router v7 + Tailwind v4로 스택은 동일합니다. 차이는 **정보 구조(IA)와 화면 흐름**에 있습니다.

---

## 1. 로그인 후 첫 화면 — 프로젝트 목록 → "안내 + 목록"

**기존:** 로그인 성공 시 `/project-list`로 이동. 헤더 한 줄 안내 + 프로젝트 카드 목록뿐. 시스템이 무엇을 해주는지, 어떤 방식이 있는지에 대한 소개 영역이 없음.

**목업:** 홈(`/`) 상단에 **시스템 소개 영역(SystemIntro)** 추가.
- 시스템 설명 문단 + "탄소발자국 산정" CTA
- 두 가지 산정 방식 카드 (MRV 기반=인증 가능 / 계산기=참고용), 각 카드에서 서비스 안내로 이동
- 그 아래에 프로젝트 목록 배치

→ **처음 들어온 사용자도 "이 시스템이 뭘 하는 곳인지" 즉시 이해**하도록 첫 화면 성격을 '허브'에서 '안내+허브'로 전환.

---

## 2. 서비스 안내 페이지 신설 (`/guide`)

**기존:** 별도의 개념/서비스 안내 페이지 없음. 사용자는 배경지식 없이 바로 폼을 마주함.

**목업:** 학습형 **서비스 안내 페이지** 신설.
- **LCA(전과정평가) 개념 설명** + **커피 전과정 7단계 흐름도**(재배→수송→로스팅→포장→유통→사용→폐기)를 아이콘+화살표로 시각화
- **시작 시 정하는 3가지 축**(방식/방법론/범위) 설명
- 하단 **선택 시뮬레이터**: 방식/방법론/범위를 조작하면 → 실제 진행하게 될 단계와 필요 서류 체크리스트를 실시간 미리보기 → "이 방식으로 시작하기"로 바로 진입

→ **LCA를 모르는 로스터리 담당자의 진입 장벽 완화** 목적.

---

## 3. 신규 프로젝트 시작 흐름 — 즉시 생성 → 3단계 시작 위저드

**기존:** 프로젝트 목록에서 "새 프로젝트 생성" 클릭 시 **기본값 고정**(`track: mrv, boundary: gate, methodology: iso14067, specVersion: v2`)으로 즉시 생성 후 곧바로 기본정보 화면 진입. 방식 선택은 이후 기본정보 폼 안에서 처리.

**목업:** 별도의 **시작 위저드(`/start`)** 로 산정 방식을 먼저 결정.
- 3단계 순차 선택: **① 산정 방식(MRV/계산기) → ② 방법론(ISO/환경성적표지) → ③ 산정 범위(생산까지/폐기까지)**
- 조건부 규칙을 UI에서 안내: 계산기 선택 시 방법론 단계 자동 건너뜀(ISO 자동), 환경성적표지(EPD) 선택 시 범위 "폐기까지" 고정(잠금)
- 마지막에 선택 조합 요약(인증가능/참고용 배지 + 총 단계 수) 제공 후 프로젝트 시작

→ 방식 선택을 **폼 필드에 묻어두지 않고 독립된 의사결정 단계로 승격**. (규칙 로직 자체는 양쪽 동일: 계산기→ISO, EPD→폐기까지)

---

## 4. 진행 단계 시각화 — 세로 사이드바 → 상단 가로 스텝 네비 추가

**기존:** 프로젝트 작업 공간의 단계 이동은 **좌측 세로 사이드바 메뉴**로만 표현. 상단 진행바/스텝 인디케이터 없음. 현재 어느 단계인지, 전체 중 몇 번째인지 한눈에 보기 어려움.

**목업:** 작업 화면 상단에 **가로 스크롤 스텝 네비(공정 흐름 형태)** 추가.
- 각 단계 카드에 "STEP n" + 단계명 + **상태 미니 배지**(필수완료/미입력, OCR완료/대기, 자동계산, 점검, 결과확인)
- 현재 단계 강조, 클릭 시 해당 단계로 이동
- 단계들이 준비/제조전/제조/제조후/마무리 **공정 단계(phase)로 그룹핑**되어 흐름으로 인지됨

→ 기존의 세로 메뉴 방식 대신(또는 병행) **"내가 지금 전체 공정 어디에 있는지"를 상단에서 즉시 파악**.

---

## 5. 각 단계 상단 설명 추가

**기존:** 페이지 상단에는 상단바 제목 한 줄만 있고, "이 단계가 무엇이고 왜 필요한지" 설명이 없음. 설명은 각 섹션(카드) 헤더 아래 회색 부연으로 산발적으로 존재.

**목업:** 모든 작업 단계 상단에 **표준 설명 카드**를 항상 노출.
- 한 줄 요약 + 3분할 카드: **목적 / 입력하는 정보 / 얻는 결과**
- 비전문가(LCA 모르는 담당자) 눈높이 문구로 작성
- 위저드 각 단계, 서비스 안내에도 동일한 설명 원칙 적용

→ **"쉬운 용어 + 설명" 원칙을 화면 전체에 일관 적용.** (예: 제조전단계, 누적질량기여도 등 전문 용어에 쉬운 설명 병기)

---

## 6. 프로젝트 목록 카드 개선

**기존:** 1열 리스트 카드. 생성일/상태/트랙/경계 배지 + 진입·삭제 버튼.

**목업:** **반응형 그리드 카드**로, **상태에 따라 카드 내용과 액션이 달라지는 단일 재사용 컴포넌트**.
- 작성중/검토중 → 진행률 바 + "이어서 작성 / 검토 이어가기"
- 완료 → 결과값 표시 + "결과 보기"
- 트랙/방법론/경계 배지 + 상단에 상태 요약칩(작성중/검토중/완료 카운트)
- 점선 "새 프로젝트 추가" 카드 포함

## 7. 참고: 구현 범위 및 주의사항 (개발팀 전달용)

목업은 **UI/UX 방향 제시용**이며 다음 사항을 유의:

- **미구현 화면:** MRV 트랙 세부 입력 단계(문서 업로드, 원부자재, 수송, 제조, 유통 등)는 목업에서 "준비 중" 자리표시자 상태. 실제 폼이 완성된 화면은 **기본정보 + 계산기 트랙 6화면**뿐. → 나머지 단계의 **상단 스텝/설명 프레임만 참고**하고 폼 내용은 기존 구현 재사용 권장.
- **데이터:** 목업은 백엔드 없이 하드코딩 데이터 + `alert` 목업 액션.
- **단계 정의 소스:** 
  - 기존은 `lib/workflow-steps.ts` 단일 소스로 사이드바/가드/테스트가 공유.
  - 목업은 `src/data/workflow.ts`에 12단계 마스터 + 5개 워크플로우 조합 정의. → **상단 스텝 네비를 기존에 이식할 때 이 워크플로우 엔진 구조를 기존 `workflow-steps.ts`와 매핑** 필요.
- **양쪽 공통 도메인 3축 모델은 동일:** Track(mrv/calculator) × Methodology(iso/epd) × Boundary(gate/grave), 의존 규칙(계산기→ISO, EPD→폐기까지)도 동일하므로 데이터 모델 변경은 불필요.
- **설정 화면(`/settings`)** 은 목업에서 라우트 미구현(기존은 존재).

---

## 8. 개발팀 논의 포인트 (제안)

1. 상단 가로 스텝 네비를 **기존 세로 사이드바와 병행할지, 대체할지** 결정 필요.
2. 시작 위저드 도입 시 **기존 "즉시 생성" 흐름 폐기 여부** 결정 필요(기존은 목록→즉시 draft 생성).
3. 서비스 안내 페이지(`/guide`)의 선택 시뮬레이터를 **시작 위저드와 통합할지 별도 유지할지**.
4. 각 단계 상단 설명 카드의 **콘텐츠(목적/입력/결과) 문구 확정 주체** 필요.
