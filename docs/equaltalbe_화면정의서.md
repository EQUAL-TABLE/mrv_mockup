# 0. 문서 개요

## 용어 정의

| 화면 표시 용어 | 내부 관리 용어 | 설명 |
| --- | --- | --- |
| 고지서 기반 탄소회계 | MRV 트랙 | OCR 인보이스·고지서 업로드 기반. 1차 데이터 기반 산출. 결과확인서·보고서 발급 가능 |
| 추정치 기반 탄소발자국 계산 | 계산기 트랙 | 수동 폼 입력 기반. 문헌값(일반데이터) 적용. 문서 발급 불가. "참고용, 인증 불가" 자동 명시 |
| Cradle-to-Gate | C2Gate | 제조전단계 + 제조단계까지 |
| Cradle-to-Grave | C2Grave | C2Gate + 제품유통 + 사용단계(ISO만) + 폐기단계 포함 |
| 검토 | (통일 용어) | 검토단계 화면에서 수행하는 오류·경고 일괄 점검 행위. |
| 확정 | (통일 용어) | 검토단계에서 실행하는 최종 잠금 처리. "검토"와 별도 행위 |
| 저장 | (통일 용어) | 페이지별 입력값 저장 동작. |
| Manager | (권한 용어) | 프로젝트 생성·삭제(C·D) 권한 보유. 단계별 데이터 CRUD 가능 |
| Member | (권한 용어) | 프로젝트 C·D 불가. 할당된 프로젝트 내 단계별 데이터 CRUD 가능 |

**용어 통일 원칙**: 문서 서술 전반은 "트랙"으로 통일. Section 1의 UI 필드 라벨 "산정 유형"은 화면상 실제 표시명으로 그대로 유지(표시명과 서술용어 병존 허용).

## 공통 UI 원칙

### 상단 우측 버튼 영역

- 전 화면 공통: `[이전] [다음] [저장]`
- 검토단계 화면 한정: `[이전] [다음] [저장] [검토] [확정]`
- 예외(읽기전용·전량 자동산출 화면 — ⑤누적질량기여도, ⑧사용단계, ⑨폐기단계-수송, 계산기 트랙 ⑩폐기단계-처리): `[이전] [다음]`만 표시
- 예외(⑫결과, 최종 화면): `[이전]`만 표시

### 버튼 동작

| 버튼 | 동작 |
| --- | --- |
| 저장 | 현재 페이지 입력값 저장. 舊 "임시저장" 명칭 대체. 자유롭게 반복 가능 |
| 이전/다음 | 페이지 이동. 데이터 저장 여부와 무관하게 이동 가능 |
| 검토 (검토단계 화면 전용) | 24개 항목(그룹1~6) 일괄 오류·경고 점검 실행 |
| 확정 (검토단계 화면 전용) | 접근 권한: **Manager 전용**. 활성화 조건: 오류 0건 + 경고 항목 전체 확인체크 완료. 실행 시 OCR 추출 데이터·첨부파일 잠금. ⑫결과 화면으로 이동 |

### 도움말 아이콘

- 산정 로직에 영향을 주거나 표준 근거가 있는 입력 항목 우측에 "?" 원형 아이콘 배치
- 클릭/호버 시 해당 항목 설명(용도, 산정 영향 등) 툴팁 표시
- 자명한 항목(이메일, 연락처 등)은 생략 가능
- 문구 소스: 화면정의서의 "비고" 컬럼 재사용하지 않음. **별도 사용자향 UX 라이팅 작업으로 분리**(사용자 이해도 우선, 개발 참조용 문구와 톤 분리 필요) → 부록 "미결 항목"에 등재

### OCR 데이터 처리

- 확정 전: OCR 대상 파일 재업로드·변경 가능
- 확정 후: 첨부 파일 및 OCR 추출 데이터 변경 불가. 오류 발생 시 시스템 관리자 문의
- OCR 추출값: 사용자 수정 가능. 수정 이력 자동 기록(필드명/수정전후/수정자/타임스탬프). 확정 후 변경 불가

### 오류/경고 판정 구조

- 페이지별 개별 검사 없음. 전 항목 검토단계 화면에서 일괄 점검
- 판정 결과 3종: 정상 / 경고(진행 허용, 확인체크 필요) / 오류(진행 차단, 수정 필요)
- 오류 항목 클릭 시 해당 입력 화면으로 이동 → 수정 후 재검토 가능

### 검토 진입 방식

| 상황 | 동작 |
| --- | --- |
| 최초 진입 | 해당 트랙의 검토단계 이전 전 페이지 데이터 입력 완료 시, 검토단계 진입과 동시에 자동 검토 실행 |
| 데이터 수정 후 재진입 | "데이터 수정이 확인됩니다. 다시 검토를 진행해주세요." 안내 문구 표시. `[검토]` 버튼으로 수동 재실행 |

> 출처: equaltable_mrv_design.md §1, §5 / equaltable_6월_신규설계.md §11 + 본 대화 확정사항

## 프로젝트 상태 관리

**MRV 트랙**
```
데이터 입력 중 (페이지별 저장) → 검토단계 (자동/수동 검토) → 확정 → 결과 확인 → 보고서 발행
```

| 상태 | 규칙 |
| --- | --- |
| 데이터 입력 중 | 페이지별 저장 자유. 파일 재업로드 가능 |
| 검토단계 | 확정 전 진입. 오류 항목 클릭 → 해당 입력화면 이동·수정 가능. 재검토 반복 허용 |
| 확정 | 검토단계 상단 버튼. Manager 전용. 오류 0건 + 경고 전체 확인체크 완료 시 활성화. OCR 추출 데이터·첨부 파일 변경 불가 |
| 보고서 발행 | PDF 발급. 확정된 프로젝트에 한해 Manager·Member 모두 발행 가능. 재발행 자유(최초 스냅샷 계속 사용) |
| 발행 후 EF 업데이트 | 최초 확정 시점 EF DB 버전 스냅샷 고정. 이후 EF 업데이트와 무관하게 수치 재현 |

**계산기 트랙**
```
데이터 입력 중 (페이지별 저장) → 결과 확인 (검토단계 없음)
```

**프로젝트 단위 정의**: "산정 유형 × 시스템 경계 × 기준년도" 조합. 표준 선택·트랙 선택·시스템 경계는 생성 시 확정, 이후 변경 불가(단, C2Grave 방법론 교체는 예외 허용)

> 출처: equaltable_mrv_design.md §4, §5 + 본 대화 확정사항

## 📌 Section 1 — 산정 설정

### **목적/개요**

산정 유형(MRV/계산기)·방법론(ISO 14067/환경성적표지)·시스템경계(C2Gate/C2Grave)를 확정하는 섹션. 전체 항목 생성 후 변경 불가 원칙(방법론만 예외).

### **항목 정의**

- equaltable_data_fields.md §1 Section 1 참조

### **조건부 렌더링 규칙**

```
1) 방법론 = 환경성적표지
   → 시스템 경계: C2Grave 고정 표시, 선택 UI 비활성화
   → 작성 방식: Option A(신규작성) / Option B(C2Gate 연동) 표시
   → Option B: 조직 내 전체 프로젝트 중 확정 완료 상태의 ISO 14067 C2Gate 프로젝트 목록 표시
                + 안내문구 "투입물 리스트 연동 후 환경성적표지 EF로 재계산됩니다"

2) 방법론 = ISO 14067, 시스템 경계 = C2Gate
   → 작성 방식 섹션 비표시

3) 방법론 = ISO 14067, 시스템 경계 = C2Grave
   → 작성 방식: Option A / Option B 표시
   → Option B: 조직 내 전체 프로젝트 중 확정 완료 상태의 ISO 14067 C2Gate 프로젝트 목록 표시

4) Option B 선택
   → 연동 프로젝트 선택은 생성 시점 1회만 가능. 저장 후 변경 불가
   → 출고량(Y, kg RC) 입력 필드 표시
   → 연동 프로젝트 기준년도 ≠ 현재 기준년도 → 경고 표시, 진행 허용
```

### **생성 후 변경 불가 항목**

산정 유형, 시스템 경계, 작성 방식, 연동 프로젝트, 출고량 — 전체 불가

### **방법론**

예외적으로 C2Grave 프로젝트에 한해 생성 후 교체 허용 (ISO ↔ 환경성적표지)

### **계산 로직 요약**

- 방법론 교체(C2Grave 한정) 시: 포장재 자동 재분류 실행
  - ISO → 환경성적표지: 키워드 DB 기반 자동 매핑(최소포장재/출하포장재 구분) → 사용자 확인 UI 노출 → 미분류 항목은 수동 지정
  - 환경성적표지 → ISO: 최소포장재+출하포장재를 "포장재" 단일 분류로 자동 병합
- 방법론 교체 시 누적질량기여도 재분석 여부: 출하포장재가 추가/제거되는 경우만 재분석 트리거, 단순 EF 교체는 재분석 불필요

### **연계 데이터**

방법론 변경 결과 → ⑤누적질량기여도(재분석 트리거), ③제조전단계-원부자재(포장재 재분류)

기능단위 숫자(N) → ⑫결과 화면 배율 적용

## 📌 Section 3 — 작성자 정보

### **목적/개요**

사업장 정보(회원정보 연동)와 프로젝트 담당자 정보를 등록하는 섹션.

### **항목 정의**

- equaltable_data_fields.md §1 Section 3 참조

### **조건부 렌더링 규칙**

계산기 트랙은 본 섹션 자체가 존재하지 않음(화면 미표시). 계산기 트랙은 인증·검증 목적 문서를 발급하지 않으므로 작성자·사업장 정보 수집의 실익이 없다고 판단하여 전면 삭제함.

### **생성 후 변경 불가 항목**

사업장명, 사업자등록번호, 사업장 주소 — 회원정보 연동값으로 프로젝트 단위 수정 불가. 담당자명·연락처·이메일은 프로젝트 단위 수정 가능

   → dLUC 배출량·흡수량 필드: 증빙문서에 항목별로 구분 기재된 경우만 OCR 추출(선택). 결과·보고서 표시 전용

> "황마 자루(1,000g/ea)와 PP 자루(300g/ea) 동시 사용을 기본값으로 가정하여 산정함. 실제 사용 재질과 상이할 수 있음."

## 📌 Section E-2 — 출하포장재 · 테이프

### **목적/개요**

- 박스 규격 기반 테이프 사용량 자동 산출
- 재질(OPP/크라프트)에 따라 배출량 산정 방식 상이

### **항목 정의**

- equaltable_data_fields.md §3 Section E-2 참조

### **조건부 렌더링 규칙**

```
재질 지정 방식 = OPP
  → OPP 사용 면적(m²) 자동 계산 (배출량 산정 전용, 화면 미표시)
  → 배출량 산정 시 면적기준 EF(kg CO₂e/m²) 적용

재질 지정 방식 = 크라프트
  → 총 사용 중량(kg) 기준 EF(kg CO₂e/kg) 적용
```

### **계산 로직 요약**

- 단위 기간 테이프 사용량(m) = (4W+2D) × 단위 기간 박스 사용량
- 총 사용 중량(kg) = 테이프 사용량 × 재질별 g/m (크라프트 6.5g/m / OPP 3.5g/m, 재질 무관 항상 계산 — 폐기량 산정용)
- OPP 사용 면적(m²) = 테이프 사용량 × 0.048 (폭 고정, OPP 선택 시만 계산)
- 배출량: 크라프트 = 총 사용 중량 × EF(kg/kg) / OPP = OPP 사용 면적 × EF(kg/m²)

**보고서 자동 기재 문구**
> "테이프 사용량은 박스 치수(W·D) 기반 4W+2D 공식으로 산출한 추정값임."
> "테이프 단위 무게는 시중 유통 제품 스펙(크라프트 6.5g/m / OPP 3.5g/m) 기반 기본값 적용. 실제 제품 스펙과 차이가 있을 수 있음."
> "OPP 폭 48mm는 제품 스펙 기준 고정값. 폐기단계 발생량은 재질 무관 질량(kg) 기준 산정."

### **연계 데이터**

총 사용 중량 → ⑩폐기단계-처리-Section1 (출하포장재발생량, 재질 무관 항상 연동)

**수송량 데이터 참조 방향**
> 수송량은 ⑩폐기단계-처리 화면의 저장 결과를 기다리는 것이 아니라, ③~⑦ 각 화면 저장 시점에 이미 자동 누적된 폐기물 발생량 데이터를 직접 참조함. 화면 순서(⑨→⑩)와 데이터 의존 방향은 무관.

**배출량 산식**
```
수송량 = 각 폐기물 항목별 누적 발생량 (③A-2/D2, ⑥SectionD, ⑦저장시자동처리 등에서 저장 시점 자동 누적된 값)
배출량(kg CO₂e) = Σ(처리방식별 비율 × 거리 × 수송량 × 트럭EF)
```
배출량: **⑫결과에서만 표시**

**보고서 가정사항 자동 기재**
> "폐기물은 전국 폐기물 발생 및 처리현황 통계 기준 소각·매립·재활용 비율에 따라 각 처리시설로 수송된다고 가정함. 수송 거리는 폐기물 발생 위치(납품처 또는 로스터리) 시군구 기준 각 처리방식별 공공폐기물처리시설까지의 거리를 적용함."

## 📌 Section 2 — 폐기물 처리 방식 · MRV 트랙

### **목적/개요**

- 재활용 위탁처리 증빙서류 선택 시 해당 중량만큼 재활용 증빙분으로 우선 처리
- 잔여량은 국가 통계 비율 자동 적용

### **항목 정의**

- equaltable_data_fields.md §10 Section 2(MRV) 참조

### **조건부 렌더링 규칙**

```
재활용 위탁처리 증빙서류 선택
  → 재활용 처리 폐기물 종류, 재활용 처리 중량 필드 필수 전환

재활용 처리 중량 > 해당 품목 발생량
  → 발생량 상한 자동 적용. 초과분 무시. 사용자에게 경고 표시. 타 품목 이월 불가

증빙서류 내 품목 미명시
  → 해당 증빙 무효 처리
```

### **계산 로직 요약**

**처리 구조**
- 재활용 증빙 제출 시: 품목별 독립 처리(타 품목 초과분 이월 불가)
  - 증빙 중량 ≤ 발생량: 증빙 중량 전량 재활용 인정
  - 증빙 중량 > 발생량: 발생량까지만 인정, 초과분 무시
  - 재활용 인정량 → 수송 EF만 반영, 처리 EF = 0
  - 잔여량 → 국가 통계 비율 적용
- 증빙 미제출 시: 전량 국가 통계 비율 자동 적용

**배출량 산식**
```
[재활용 증빙분]
  수송 배출량 = 증빙 중량(kg) × 재활용시설까지 거리(km) × 트럭 EF ÷ 1,000
                (⑨폐기단계-수송에서 산출된 재활용시설 거리 자동 연결)
  처리 배출량 = 0

[잔여량 / 증빙 미제출 전량]
  처리 배출량 = Σ(잔여량 × 처리방식별 비율 × 처리방식별 EF)
```
배출량: **⑫결과에서만 표시**

### **연계 데이터**

- 재활용 위탁처리 증빙서류 ← ②OCR문서업로드-#15
- 재활용시설 거리 ← ⑨폐기단계-수송

# ADMIN 관리자 기능

## Admin 일반

### 🟦 관리자 로그인

- 이메일과 비밀번호로 인증한다. 2단계 인증(2FA)은 적용하지 않는다.
- 로그인 성공·실패 이력(일시, IP)을 기록하며, 관리자 본인이 자신의 접속 이력을 조회할 수 있다.

---

### 🟦 사용자 관리

- 시스템 내 전체 사용자를 조회·관리하는 화면이다.

#### Section 1. 목록

- 소속 조직, 역할(Manager/Member), 상태(활성/정지/탈퇴)로 필터링한다.
- 이름, 이메일, 소속 조직, 역할, 상태, 가입일, 최근 로그인일을 목록에 표시한다.

#### Section 2. 상세

- 사용자 기본정보(이름, 이메일, 연락처)를 조회한다.
- 역할을 변경한다(Manager ↔ Member).
- 상태를 변경한다(활성화/정지/탈퇴 처리).
- 비밀번호 초기화를 대행한다(재설정 링크 발송).
- 로그인 이력(일시, IP, 기기)을 조회한다.

---

### 🟦 조직 관리

- 시스템 내 전체 조직(고객사)을 조회·관리하는 화면이다.
- 신규 조직은 회원가입 시 사업자등록증 OCR 인식 후 **admin 사전승인 없이 즉시 활성화**된다. Admin은 활성화 이후 사후적으로 정지 조치만 수행한다.

#### Section 1. 목록

- 조직명, 사업자등록번호, 대표 담당자, 소속 사용자 수, 프로젝트 수, 가입일, 상태를 목록에 표시한다.

#### Section 2. 상세

- 회원가입 시 OCR로 추출된 사업자정보(사업장명, 사업자등록번호, 주소)를 조회한다.
- 소속 사용자 목록을 조회하며, 각 사용자는 사용자 관리 화면 상세로 이동할 수 있다.
- 조직 상태를 변경한다(활성 → 정지).
- 소속 사용자가 업로드한 문서는 본 화면 또는 사용자 상세에서 연결 조회 가능하며, 열람 정책은 문서 열람 섹션 원칙을 따른다.

> 권한 관리는 별도 화면을 두지 않는다. Manager/Member 2단계 구조가 고정되어 있어, 사용자 상세의 역할 변경 기능으로 충분하다. Admin 계정 자체는 Super Admin 단일 권한으로 운영하며 하위 admin 권한 분리는 두지 않는다.

---

### 🟦 배출계수 관리

- 본 화면에서는 시스템에 적용되는 배출계수(kg CO₂e 단위 값)의 조회·버전 이력 관리·신규 버전 등록을 수행한다.
- 관리 대상: 원부자재 EF, 수송 EF, 제조단계 EF(전력·연료연소·환경성적표지 에너지), 폐기단계 처리 EF.
- 전력 배출계수(EG-TIPS)는 연도별 행으로 관리하며, 동일 연도 값은 덮어쓰지 않고 신규 연도 행만 추가한다.
- 에너지원별 탄소발자국 계산값(전력EF·연료연소EF·NCV 조합값)은 관리자가 직접 입력하지 않으며, 기반 항목(전력EF·연료연소EF·NCV) 갱신 시 시스템이 자동 재계산한다.

#### Section 1. 목록

- 표준(ISO 14067 / 환경성적표지), LCA 단계(원부자재/수송/제조/폐기), 활성 상태(현재 버전/과거 이력)로 필터링한다.
- 항목명, 값, 단위, 출처, 적용 표준, 현재 버전, 최종 갱신일, 갱신자, 데이터 품질 종합 점수를 목록에 표시한다.
- 항목 선택 시 상세/이력 화면으로 이동한다.

#### Section 2. 상세 및 버전 이력

- 현재 적용값과 과거 전체 버전을 시간순으로 표시한다. 각 버전에는 값, 등록일, 등록자, 등록 사유가 포함된다.
- 각 버전을 선택하면 해당 버전의 데이터 품질 평가(기술적·지리적·시간적 대표성, 정밀성, 완전성, 일관성 6항목 점수 및 근거)를 조회할 수 있다.
- 레코드 직접 수정은 불가하며, 값을 변경하려면 신규 버전 등록만 가능하다.

#### Section 3. 신규 버전 등록

- 입력 항목: 값, 단위, 출처(문헌·기관명 및 발행연도), 적용 시작일(기본값: 등록일+24시간)
- [등록] 클릭 시 확인모달 표시(입력값 요약 + 적용시작일 안내) → [확정 등록] 시 저장
- 등록 직후 목록 화면에 "적용대기중" 뱃지로 표시. 적용시작일까지 [등록취소] 가능
- 세부 처리 로직(자동전환·유예기간 중 계산 기준)은 기능정의서 ADM-EF-002 참조
- GWP 처리방식(실적용/출처값 인용)은 ISO 14067 항목에 한해 참고 정보로 표시하며 수정 불가(고정값)
- 데이터 품질 평가 6항목 점수(1~5 선택) 및 항목별 근거를 함께 입력한다
- 전력 배출계수 등 연도형 항목은 연도 선택 + 값 입력의 간소 폼으로 별도 제공

---

### 🟦 기준 데이터 관리

- 본 화면에서는 배출계수 산정에 사용되는 비-배출량 상수(수율·함수율·처리비율·NCV·단위환산계수 등)의 조회·버전 이력 관리·신규 버전 등록을 수행한다.
- 관리 대상: 로스팅 수율, 에너지원별 순발열량(NCV), 가스 단위 환산계수, 커피박 함수율, 폐기물 처리 비율, 사용단계 전력 원단위.
- 화면 구조·수정 방식(스냅샷 원칙)은 배출계수 관리 화면과 동일하게 적용한다.

#### Section 1. 목록

- 항목명, 값, 단위, 출처, 현재 버전, 최종 갱신일을 목록에 표시한다.
- 항목 선택 시 상세/이력 화면으로 이동한다.

#### Section 2. 상세 및 신규 버전 등록

- 배출계수 관리 화면과 동일한 패턴(값·출처·데이터 품질 평가·버전 이력·**24시간 유예 원칙**)을 적용한다.
- 폐기물 처리 비율과 같이 복수 하위값으로 구성된 항목(재활용/소각/매립 비율)은 세트 단위로 신규 버전을 등록하며, 등록 시 하위값 합계 100% 검증을 수행한다.
- 세부 처리 로직은 기능정의서 ADM-MASTER-001 참조

---

### 🟦 참조 데이터셋 관리

- 배출계수·기준데이터와 달리 단일 값이 아닌 **대량 레코드로 구성된 목록형 마스터 테이블**을 관리하는 화면이다.
- 배출계수 관리·기준데이터 관리 화면과는 별도의 독립 화면으로 운영한다.

#### Section 1. 폐기물 처리시설 위치 DB

- (기존 내용 유지)
- 일괄 업로드(CSV/Excel) 또는 개별 수동 추가 완료 시 확인모달(변경 건수 + 적용시작일) 표시 후 "적용대기중" 상태로 저장
- 적용시작일 기본값: 등록일+24시간. 유예기간 중 [등록취소] 가능
- 세부 처리 로직은 기능정의서 ADM-REF-001 참조

#### Section 2. 물질 정규화 DB

- (기존 내용 유지)
- Section 1과 동일한 24시간 유예 원칙 적용
- 세부 처리 로직은 기능정의서 ADM-REF-002 참조

---

### 🟦 감사로그

- Admin 자신의 조작 이력만을 대상으로 한다. 사용자의 프로젝트 내 행위(OCR 수정 등)는 각 프로젝트의 자체 이력 관리로 별도 처리하며 본 화면 대상이 아니다.
- 기록 대상: 배출계수·기준데이터·참조 데이터셋 신규 버전 등록(일괄업로드·개별 수동추가 포함), 사용자 상태·역할 변경, 조직 상태 변경, 시스템 설정 변경, 고객 업로드 문서 원본 열람.
- 목록에는 조작일시, 조작자(admin 계정), 조작 유형, 대상(사용자명/조직명/항목명), 변경 전값, 변경 후값, 사유(입력된 경우)를 표시한다.
- 조작유형·조작자·기간으로 필터링한다.
- 본 화면은 조회 전용이며, 로그 자체는 수정·삭제할 수 없다.

---

### 🟦 문서 열람 (고객 업로드 문서 대응)

- 별도 메뉴가 아니라 조직 상세·사용자 상세 화면 내에서 접근한다.
- 평시에는 문서 목록(파일명, 문서종류, 업로드일, OCR 처리상태)과 OCR로 추출된 구조화값만 조회 가능하다.
- 원본 이미지 파일 열람은 예외적 기능으로 별도 제공한다.
  ※ 여기서 "원본"은 OCR-006(PII 마스킹) 처리가 완료된 후 서버에 저장된 파일을 의미하며,
    마스킹 이전 상태의 이미지는 서버에 존재하지 않는다(개인연락처·주민번호·카드번호 등은
    업로드 시점에 이미 제거됨).
  열람 시 사유(OCR 오류 확인/기타 직접입력)를 선택·입력해야 하며, 열람은 즉시 이루어지되
  감사로그에 자동 기록되고 해당 고객사에는 사후 알림이 발송된다("관리자가 OO 문서를 열람함").

---

### 🟦 시스템 설정

- 비밀번호 규칙(최소 길이, 복잡도 조건)을 설정한다.
- 세션 만료 시간을 설정한다.
- Feature flag·외부연동 API 키 관리는 본 범위에 포함하지 않는다.

---

### 🟦 고객지원(CS) 대응

- 별도 CS 티켓 화면은 두지 않는다. 고객 문의는 외부 이메일로 접수한다.
- 문의 대응 시 admin은 사용자 관리·조직 관리·문서 열람 화면에서 해당 고객사를 조회하여 대응한다.
- 고객 계정 대신 로그인(Impersonation) 기능은 채택하지 않는다.
- 결제·구독 관리(플랜, 과금)는 현재 과금 모델 자체가 미정으로 본 설계 범위에서 제외하며, 별도 세션에서 진행한다.
