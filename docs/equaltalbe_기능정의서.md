## CMN 공통인증
 
> "테넌트(Tenant)"는 사업자등록번호 1개 단위로 부여되는 논리적 데이터 격리 구획을 의미함.
> 권한체계: Manager / Member 2단계 (Owner·Auditor 역할 없음)


### USER - 사용자

#### USER-001 회원가입

- 기능: 사업자등록증 OCR로 사업장정보 자동추출, 담당자정보 직접입력으로 계정 생성. 사업자등록번호 기준으로 기존 테넌트 존재여부 자동판별
- 관련화면: /signup
- 처리흐름: 사업자등록증 업로드 → OCR 추출(사업장명·사업자등록번호·주소·업종) → 사업자등록번호로 기존 테넌트 매칭
    - 매칭 안됨(신규 사업자): 테넌트 자동생성 + 해당 가입자 Manager 자동부여 + 즉시 활성화
    - 매칭됨(기존 테넌트 존재): 계정은 생성되나 승인대기 상태로 보류, 해당 테넌트 Manager 전원에게 승인요청 알림 발송
- 예외: 사업자등록번호 중복 시(이미 승인완료된 동일 계정) 로그인 유도, 파일 형식 미지원 시 안내
- 비고: 승인대기 상태에서는 로그인 가능하나 대시보드 외 기능 접근 불가

---

#### USER-002 로그인

- 기능: 이메일·비밀번호로 인증. 인증 성공 시 대시보드 이동
- 관련화면: /login
- 예외: 이메일 미등록 시 오류안내, 비밀번호 불일치 시 오류안내, 승인대기 상태 계정은 로그인은 되나 제한된 화면만 노출

---

#### USER-003 내 정보 조회·수정

- 기능: 사업장정보(읽기전용, OCR 확정값)와 담당자정보(수정가능) 조회·수정
- 관련화면: /profile
- 예외: 사업장정보(사업장명·사업자등록번호·주소·업종)는 수정불가, 담당자 이메일 중복 시 오류안내

---

#### USER-004 가입 승인 처리

- 기능: Manager가 자신의 테넌트에 승인대기 중인 신규 가입자를 조회하고 승인·거부 처리. 승인 시 권한(Manager/Member) 지정
- 관련화면: 대시보드 내 승인대기 위젯 또는 별도 팀관리 화면
- 처리흐름: 승인대기 목록 조회 → 대상자 선택 → 권한 지정 → 승인 또는 거부 → 승인 시 계정 즉시활성화+알림발송, 거부 시 계정 비활성처리+사유안내
- 권한: Manager 전용
- 예외: 승인대기 0건 시 빈 상태 안내, 테넌트 내 최소 1명 Manager 유지 필요

### 1. 프로젝트 공통


#### PROJ-001 프로젝트 목록 조회

- 기능: 테넌트 내 프로젝트 목록 시트 조회. 프로젝트명·작성일·상태·산정유형·시스템경계·기준년도 표시
- 관련화면: /projects
- 표준분기: 없음
- 권한: Manager 전체 조회 / Member 할당 프로젝트만
- 예외: 0건 시 생성 유도 안내

---

#### PROJ-002 프로젝트 생성(기본정보 입력) — MRV/CAL 공유

- 기능: 신규 프로젝트 생성 및 기본정보(산정설정·프로젝트정보·작성자정보·생산정보) 입력
- 관련화면: /projects/new(신규생성), /projects/:id/basic (기본정보 RU)
- 표준분기 - 시스템경계 선택
    - ISO는 C2Gate/C2Grave 선택 가능,
    - 환경성적표지는 C2Grave 고정(사용단계 제외 안내 자동 노출)
- 입력값:
    - 산정유형(MRV·계산기)
    - 방법론(ISO·환경성적표지, 단일선택)
    - 시스템경계
    - 작성방식(C2Grave만: OptionA 신규작성/OptionB C2Gate연동)
    - 프로젝트명·기준년도·데이터수집기간
    - 기능단위 N(kg)
    - 담당자정보
    - 단위기간 총원두생산량
    - 로스터기 연료유형
    - 블렌딩여부·비율
    - 사용단계 시나리오(ISO·계산기 C2Grave만)
- 출력값:
    - 프로젝트ID 발급
    - 기본정보 저장완료
- 처리흐름:
    - 산정설정 선택 → 프로젝트정보 입력 → 작성자정보 확인 → 생산정보 입력(블렌딩 Y시 비율합계100% 검증) → 저장
- 생성 후 변경 불가 항목:
    - 산정유형
    - 시스템경계
    - 작성방식(Option A/B)
    - 연동프로젝트·출고량(Option B)
    - 사용단계시나리오
    - 기능단위 숫자
- **방법론 변경 예외**
    - 산정유형·시스템경계 등과 달리 방법론은 예외 있음
    - **C2Grave 프로젝트에 한해 ISO↔환경성적표지 교체 허용**(C2Gate 프로젝트는 방법론도 변경 불가)
- Option B(C2Gate 연동) 요지: ISO 14067 C2Gate **확정완료** 프로젝트만 연동 가능.
    - 투입물·산출물 리스트만 승계(계산결과는 미승계).
    - 환경성적표지로 연동 시 EF 재계산.
    - 방법론 변경 시 포장재 분류(최소/출하) 자동 재매핑,
    - 누적질량기여도 재분석 여부는 변경 내용에 따라 결정
- C2Grave 프로젝트 단위 원칙: 납품처 1곳 = C2Grave 프로젝트 1개
- 예외: 기준년도·수집기간 논리 불일치 시 저장 불가
- 비고: 환경성적표지 선택 시 사용단계 스텝 자체 미노출

### 10. 검토·확정 (MRV 전용)

#### VALID-001 검토단계 자동검증

- 기능: 6개그룹 24개 항목 자동정합성 검토. 정상/경고/오류 3단계 구분. 오류항목 클릭시 해당화면 이동, 수정후 재검증
- 관련화면: /projects/:id/validation (흐름 전체 검토단계)
- 출처: 방법론 설계서(ISO 14067) §9.2, 방법론 설계서(환경성적표지) §9.2
- 검토 내용 구분
    - **기간 정합성** (5개): 전력·가스고지서 발급월, 재생에너지 발전량기록 연월, 재활용위탁처리 거래명세서 발행일 각각 수집기간 포함여부 / 생두INVOICE·B/L 발행일 근접여부
    - **필수항목 존재여부** (4개): 생두INVOICE·전력고지서 업로드여부 / 가스고지서·재생에너지설치확인서 업로드 여부와 관련 선택값 일치여부
    - **DB매핑 및 데이터품질** (3개): DB매핑 미완료항목 존재여부 / 이차데이터(문헌값) 적용구간 / OCR실패→수동입력 대체항목
    - **수량 정합성** (6개): 농장별 INVOICE거래량↔생두투입량 / INVOICE거래량↔B/L수송량 / 제품유통수송량↔생산량 / 블렌딩비율 합계100% / 재활용처리중량↔폐기물발생량 / 재활용증빙서류 품목명시여부
    - **주소 정합성** (4개): 로스터리주소·농장주소·납품처주소와 각 수송 출발지·도착지 간 시군구 단위 일치여부(불일치시 경고만, 진행허용)
    - **기타 정합성** (2개): 농장탄소배출증빙 기준년도↔프로젝트 기준년도 / 포장재 입력여부 누락검증
- 확정버튼 활성화조건: 오류0건 + 경고항목 전체 사용자확인체크 완료
- 확정후 처리: OCR데이터·첨부파일 잠금, 이후 수정불가

## OCR 모듈

### OCR-001 문서 수신 및 입력 처리

- 기능: 업로드된 문서 파일(PDF·이미지)을 수신, 파이프라인 진입 전 입력 유효성 검사, 채널별(웹·모바일) 입력 방식을 표준화된 입력 형식으로 변환
- 처리흐름: 
웹(파일 첨부 업로드) 또는 모바일(카메라 촬영·갤러리) 수신 
→ 파일 형식 검사(PDF·JPG·PNG·HEIC 등) 
→ 파일크기·해상도검사 
→ PDF는 페이지 별 이미지 변환(래스터라이즈) 
→ 문서 종류 태그 부착 
→ OCR-002로 전달
- 입력값: 문서 파일, 문서 종류 태그, 프로젝트ID, 사용자ID
- 출력값: 표준화된 이미지 배열(페이지별), 문서 메타 데이터, OCR작업ID
- 연동모듈: 호출 받음 — DOC-001(문서 일괄 업로드) / 호출함 — OCR-002
- 예외: 미지원 파일형식 시 오류반환, PDF래스터라이즈 실패 시 오류반환, 파일손상 감지 시 재업로드 요청

---

### OCR-002 이미지 전처리 (Noise Robustness 파이프라인)

- 기능: OCR 인식정확도 향상을 위해 입력이미지의 기하학적 왜곡·그림자·저품질 노이즈를 보정. TPS(Thin-Plate Spline) 비선형변환과 De-Shadow CNN을 순차 적용
- 처리흐름: 
표준화이미지 수신 
→ TPS 적용(구겨지거나 휘어진 문서 비선형변환으로 평탄화) 
→ De-Shadow CNN 적용(그림자·어두운부분 보정) 
→ 해상도정규화(DPI표준화) 
→ OCR-003으로 전달
- 성능목표치: 문서 테이블구조 복원률 93% 이상
- 예외: TPS변환 실패 시 원본이미지로 대체 후 진행, De-Shadow 보정 후 품질저하 감지 시 보정전 이미지 유지, 최소해상도 미달 시 경고플래그 부착 후 진행
- 비고: 로스터리 현장에서 실제 제출되는 문서(스마트폰촬영 영수증, 구겨진 고지서 등) 품질편차가 크므로 본 보정 없이 OCR 직접 적용 시 인식률 급락 위험 존재

---

### OCR-003 레이아웃 분할 (Document Layout Pre-segmentation)

- 기능: 전처리된 이미지에서 텍스트·표·바코드 영역을 동시 분류. LayoutLMv3 기반 한글 영수증 특화 KOR-Receipt Head 사용
- 처리흐름: 
보정이미지 수신 
→ KOR-Receipt Head 추론(텍스트·표·바코드 영역 분류) 
→ 경계좌표(bounding box) 추출 
→ 영역유형 확정 
→ OCR-004로 전달
- 성능목표치: 문서 테이블구조 복원률 93% 이상
- 예외: 영역분류 확률 임계값 미만 시 전체이미지를 단일텍스트영역으로 대체처리, 표영역 미검출 시 전체텍스트로 처리, 바코드영역 검출 시 별도 디코딩 후 메타 데이터 추가
- 비고: 한국형 비정형 고지서는 발급기관·양식마다 레이아웃이 상이해 범용OCR 직접적용 시 정확도 저하 발생. 영역 사전 분류로 필드인식 정확도 94.6% 이상 달성의 전제조건

---

### OCR-004 텍스트 인식 (Dual-Head OCR)

- 기능: 레이아웃 분할 결과 기반 영역별 텍스트 인식. Conformer(문맥인식)와 CRNN(숫자·특수기호인식)을 병렬 실행 후 Late Fusion으로 결합
- 처리흐름: 
영역별분류결과 수신 
→ 영역별 이미지크롭 
→ Conformer·CRNN 병렬실행 
→ Late Fusion 결합(최종인식텍스트+신뢰도점수 산출) 
→ OCR-005로 전달
- 성능목표치: 한국형 고지서 OCR 필드인식 정확도 94.6% 이상(F1 기준)
- 예외: 신뢰도점수 임계값 미만 필드는 저신뢰플래그 부착(수기보완 대상 표시), 양쪽 엔진 모두 인식실패 시 해당필드 공백처리 후 수기입력 유도
- 비고: 문맥정확성과 숫자정확성을 단일엔진으로 동시 달성 불가하여 특화엔진 분리 후 후반융합

### OCR-005 Key-Value 추출

- 기능: Dual-Head OCR 인식결과에서 문서유형별 필요필드(날짜·사용량·금액·출발지·도착지 등)를 Key-Value 쌍으로 추출. SPADE 위치기반 후보탐색(1단계)과 규칙사전기반 스코어링(2단계) 순차적용
- 처리흐름: 
인식텍스트 수신 
→ 1단계(SPADE 위치기반 후보탐색, 이미지전체분석으로 필드-값 후보쌍 생성) 
→ 2단계(규칙사전기반 스코어링으로 최종키-값쌍 확정) 
→ 문서종류별 산출필드 매핑 
→ OCR-006으로 전달
- 산출필드 세트:
    - 기본정보(날짜·사업자번호·상호명·거래처)
    - 거래정보(품목·수량·단가·공급가액·부가세·총금액)
    - 에너지정보(미터기지침·요금구성·계약전력·단가·사용량)
    - 운송정보(출발지·목적지·운송거리·운송수단·무게)
- 성능목표치: 필드인식 정확도 94.6% 이상, 테이블구조 복원률 93% 이상
- 예외: 필수필드 미추출 시 공백+저신뢰플래그(수기입력 유도), 동일키에 복수값 감지 시 상위신뢰도값 선택 후 원본목록 보존

### OCR-006 온디바이스 보안 처리 및 PII 마스킹

- 기능: 모바일환경에서 촬영·업로드된 이미지 내 개인식별정보(PII)를 디바이스 내에서 즉시 마스킹, 비식별화된 데이터만 서버로 전송. TensorFlow Lite/Core ML 경량모델 기반 온디바이스 추론
- 처리흐름: 
모바일 이미지캡처 
→ 경량모델 온디바이스 로드 
→ PII영역 감지(개인연락처·주민번호·카드번호 등) 
→ 즉시마스킹처리(디바이스내) 
→ 비식별화된 이미지·추출결과만 서버전송 
→ OCR-005 결과와 병합
- 예외: 온디바이스 모델로드 실패 시 서버사이드 PII마스킹으로 폴백, 웹채널은 서버사이드 PII처리 적용
- 비고: TensorFlow Lite(Android)/Core ML(iOS) 경량모델 사용

### OCR-007 테이블 구조 복원 및 자동 검산

- 기능: OCR 인식 과정에서 깨진 표 구조를 복원, 세금계산서 등 수식 검증 가능 문서에 대해 자동 검산 수행 및 이상치 탐지
- 처리흐름: 
표영역 인식결과 수신 
→ 셀구조복원(깨진 테이블구조·병합셀·누락셀 추론) 
→ 자동검산(공급가액+부가세=합계 등 문서유형별 수식검증) 
→ 이상치탐지(3σ 기반 통계모델) 
→ OCR-005에 결과 반영
- 성능목표치: 문서 테이블구조 복원률 93% 이상
- 예외: 검산불일치 감지 시 검토 필요 플래그(검토단계 경고항목으로 전달), 셀 복원 실패 시 해당 영역 수기 입력 유도, 이상치는 플래그 부착 후 진행(차단 아님)

### OCR-008 구조화 데이터 출력 및 OCR 풀 저장

- 기능: OCR 파이프라인 전단계 처리결과를 구조화 데이터로 변환, 프로젝트단위 OCR 임시풀에 저장. 이후 각 입력단계에서 풀 선택 시 자동으로 데이터필드에 채워짐
- 처리흐름: 
Key-Value추출·테이블복원결과 수신 
→ 구조화데이터 생성(필드명·값·신뢰도·원본좌표·저신뢰플래그 포함) 
→ 프로젝트단위 OCR풀에 저장 
→ OCR처리상태 업데이트(처리중→완료) 
→ 완료알림 발송
- 성능목표치: 문서 1건 전체 파이프라인 처리시간 3초 이내(전처리→OCR→정규화→EF매칭까지)
- 연동모듈:
    - 호출받음 — OCR-005, OCR-007
    - 호출함 — DOC-001 하위 각 입력단계(BEAN-001·TRANS-001·MFG-001~004·WASTE-001), NOTI-001
- 예외: 전체 파이프라인 실패 시 상태 '실패'로 업데이트+수기입력전환 유도, 부분실패(일부필드 미추출) 시 성공필드만 풀에 저장
- 비고: 확정 전까지 풀에서 재업로드·재처리 가능, 확정 후 풀데이터 변경불가

### OCR-009 OCR 처리 상태 관리

- 기능: 문서별 OCR 처리 진행 상태(대기중·처리중·완료·실패)를 관리, 사용자가 조회할 수 있도록 제공. 백그라운드 비동기 처리 구조에서 상태 추적 및 완료 알림 역할
- 처리흐름: OCR-001에서 작업ID발급+상태 '대기중' 등록 → 파이프라인 진입 시 '처리중' → OCR-008 완료 시'완료' → 실패 시'실패'+오류 코드 기록 → 상태 변경 시 알림 발송
- 관련 화면: /documents/ocr-jobs
- 예외: 처리 타임아웃 시 자동 실패 처리+재시도 유도, 실패 시 수기 입력 전환 안내
- 비고: 백그라운드 비동기 처리로 사용자가 업로드 후 다른 작업 진행 가능

### NRM-003 단위 표준화 변환

- 기능: OCR추출값·직접입력값의 다양한 단위를 표준단위로 자동환산
- 가스 단위환산 (환경성적표지 트랙, D-4-1 EF 적용 대상):
천연가스는 부피(Nm³) 기준 적용 — Nm³ 입력 시 환산 불필요, MJ→Nm³(÷38.5, 도시가스 NCV) 환산 후 적용.
LPG는 질량(kg) 기준 적용 — MJ→kg(÷46.2), Nm³ 미지원.
(참고용 질량환산 경로: 천연가스 Nm³→kg ×0.7809 KOGAS밀도, MJ→kg ÷49.4 — 배출량 산정에는 미사용) — 표준별(ISO/환경성적표지) EF소스에 따라 적용경로 상이(EFM-005 연동)
- 그 외 단위변환: 80+ 단위 포괄변환(kW→kWh, kcal→MJ, gal→L, lb→kg, oz→g, km→t·km 등), 표준상태보정(0℃·1atm), 계절별표준발열량 적용

## EFM EF매칭

### EFM-001 데이터 위계 및 EF소스 선택 원칙

- 기능: EF 적용 시 3단계 위계를 따름 — 1순위 사용자 직접입력값(측정치) → 2순위 국가공인DB(추정치) → 3순위 글로벌DB·문헌값(추정치). 
상위 순위 데이터 가용 시 하위를 자동 대체
- 트랙: 전 트랙 공통
- 비고: 이후 모든 EFM 기능의 기반 원칙. 개별 기능마다 반복 서술하지 않음

---

### EFM-002 표준별 EF DB 분리 구조

- 기능: ISO 14067과 환경성적표지는 EF소스 자체가 분리되어 별도 관리됨(단순 파라미터 교체 아님)
- EF소스(ISO): EG-TIPS + IPCC 2006 + DEFRA(수송) 등 국제·국내 혼합
- EF소스(EPD): 환경성적표지 평가계수 단일 출처(수송 국내구간 포함 전 구간)
- 비고: 이 분리 구조가 아래 EFM-004~007 각 단계별 매칭 기능의 표준분기 기준이 됨

---

### EFM-003 원부자재 EF 매칭 (생두·포장재)

- 기능: 생두·포장재 활동자료에 대해 **어느 EF소스를 탐색대상으로 할지** 규칙기반으로 결정. 최종 EF값 자체는 EFM-011이 그 소스 내에서 확정
- EF소스(ISO): 생두-글로벌문헌값(공통) / 포장재-환경성적표지평가계수(공통)
- EF소스(환경성적표지): 동일(표준분기 없음)
- 비고: 원부자재는 표준분기가 없는 예외구간이자, 생두는 소스 자체가 단일값(문헌값 1개)이라 EFM-011 탐색이 사실상 불필요한 경우가 많음. 포장재(경로B 재질비율입력)는 재질명 표현이 다양해 EFM-011 대상이 되는 대표사례

---

### EFM-004 수송 EF 매칭

- 기능: 구간별(수출국내륙·국제·수입국내륙·제품유통·폐기수송) 수송수단에 따라 **탐색할 EF소스**를 결정. 최종 레코드(운송수단별 세부계수)는 EFM-011이 확정
- EF소스(ISO): 해외·국제구간 DEFRA고정, 국내구간(수입국내륙·제품유통)만 환경성적표지기준
- EF소스(환경성적표지): 동일원칙(구간별 소스는 표준 선택과 무관하게 고정)
- 비고: DEFRA·환경성적표지 각 소스 내에도 운송수단(트럭·선박·항공)별 다수 레코드가 존재해 EFM-011 탐색대상

---

### EFM-005 제조단계 EF 매칭 (전력·가스)

- 기능: 로스팅 전력·가스 사용량에 대해 **탐색할 EF소스**를 결정. 표준분기가 가장 뚜렷한 기능. 소스 내 정확한 연도별 레코드 선택은 EFM-011이 수행
- EF소스(ISO): 전력EG-TIPS/가스IPCC2006+EG-TIPS순발열량
- EF소스(환경성적표지): 전력·가스 모두 환경성적표지평가계수 단일출처
- 비고: 가스는 종류(천연가스/LPG)별 EF소스도 함께 갈라짐. **전력EG-TIPS는 연도별 다수 레코드 관리(ADM-EF-001 연동) — 기준년도에 맞는 정확한 연도값 선택이 EFM-011의 핵심 적용사례**

---

### EFM-006 사용단계 EF 매칭

- 기능: 추출시나리오(필터·머신·콜드브루)별 분쇄·추출 전력원단위에 대해 **탐색할 문헌값 소스**를 결정
- EF소스(ISO): 문헌값 고정(표준무관)
- EF소스(환경성적표지): 해당없음(사용단계 자체 제외)
- 비고: C2Grave 한정 기능(계산기 트랙도 동일 소스 적용). 시나리오당 문헌값이 이미 단일값이라 EFM-011 탐색이 사실상 불필요

---

### EFM-007 폐기단계 EF 매칭

- 기능: 처리방식별(소각·매립·재활용) 폐기물EF에 대해 **탐색할 소스**를 결정. 재활용인정분은 처리EF=0 처리
- EF소스(ISO): 환경성적표지평가계수 기준 폐기물처리EF(표준무관 공통)
- EF소스(환경성적표지): 동일
- 비고: 폐기 EF소스는 표준분기 없음. 단 폐기-수송 자체가 ISO에서만 존재(WASTETRANS-001 연동). 폐기물 종류(가연성·재활용 등)별 다수 레코드 존재해 EFM-011 탐색대상

### EFM-008 GWP 처리 원칙 적용

- 기능: 확정된 EF에 표준별 GWP 처리 원칙을 적용
- 원칙(ISO): AR5 원칙 적용
- 원칙(EPD): 자체 특성화인자(SAR) 준용
- 비고: 산식·항목별 실적용/인용 구분은 생략. 원칙 수준만 기능정의서에 반영

### EFM-009 배출량 산정 및 Scope 분류·집계

- 표준분기: 없음(집계 로직은 공통, 결과 표시 항목만 RESULT-001에서 표준별로 상이)

### EFM-010 EF DB 스냅샷 및 버전관리

- 관리주체: 시스템 관리자(admin)가 EF 갱신, 갱신 시 버전·일시 기록

### EFM-011 EF 자동매칭 파이프라인 (계층형 그래프 탐색 + 규칙기반필터 + 임베딩유사도매칭)

- 기능: EFM-003~007이 결정한 소스(후보군) 내에서, **연도·국가·방법론·버전·단위 등 세부조건까지 반영해 최종 EF 레코드 하나를 확정**하는 전체 매칭엔진. 전력·가스·수송·폐기·원부자재·사용단계 전 활동자료가 적용대상(예외적으로 소스 내 레코드가 이미 단일값인 항목은 탐색이 자명하게 종료됨)
- 처리 단계:
    - 계층형EF그래프탐색: EFM-003~007이 정한 소스 내에서 연도·국가·방법론·버전·단위 조건으로 후보군 축소
    - 규칙기반1차필터: 명확조건(기준년도 일치, 단위 일치 등)으로 후보 추가축소 — 전체 후보의 대다수가 이 단계에서 정리됨
    - 임베딩유사도2차매칭: 규칙만으론 하나로 좁혀지지 않는 항목(활동자료 명칭이 EF DB 항목명과 정확히 일치하지 않는 경우, 예: 포장재 재질명)에 한정해 의미기반 유사도로 최종매칭
- 출력값: 매칭된 EF ID + 매칭방식(규칙/임베딩) + 매칭근거로그
- 비고: EFM-003~007이 "어디서 찾을지" 정의, EFM-011이 "그 안에서 정확히 무엇을 고를지" 정의 — 전체 활동자료에 대해 상시 작동하는 구조로, 연구개발 KPI(최종 EF 선택 정확도 87%↑, 활동자료-정답EF 1:1 매칭 테스트셋 기준)의 실제 측정대상이 됨

## AUD 감사무결성

### AUD-001 해시체인 생성 및 관리

- 기능: OCR처리→정규화→EF선택→배출량산정→확정→보고서발행 전 단계에서 각 단계 데이터의 해시를 생성하고 이전단계 해시값과 연결해 해시체인 구성·저장
- 처리흐름: 
파이프라인 각 단계(OCR·NRM·EFM·확정) 완료 시 호출 
→ 단계데이터 직렬화 
→ 해시생성(이전단계 해시값 포함) 
→ 해시체인레코드 DB저장(단계명·데이터 스냅샷·해시 값·타임 스탬프·단계 순번) → 다음 단계에 현재 해시 값 전달 → 확정 시점에 전체 체인 봉인
- 예외: 직렬화 실패 시 해당단계 재처리요청, 이전단계 해시값 미수신 시 체인단절로 간주(경고플래그+독립해시생성)

### AUD-002 해시체인 무결성 검증

- 기능: 저장된 해시체인 전체를 재순회해 각 단계 해시값의 정합성을 검증. 데이터 위변조여부 탐지 및 이상지점 특정. 제3자 검증기관 대응 및 보고서발행 전 자동실행
- 처리흐름: 
검증대상 프로젝트ID 수신 
→ 해시체인레코드 전체 시계열조회 
→ 단계별 재계산(저장 데이터스냅샷으로 해시 재생성) 
→ 재생성해시 vs 저장해시 비교 
→ 일치시 무결성확인 / 불일치 시 위변조경고플래그+불일치단계특정
- 예외: 해시체인레코드 누락(단절) 발견 시 경고+재처리 또는 관리자개입 안내, 보고서발행 전 검증실패 시 발행차단
- 비고: 보고서발행 시 자동선행실행. 무결성검증 통과 후에만 발행 진행

- 예외: 무결성검증 실패 시 봉인차단+오류상세안내, 봉인 후 데이터변경시도 시 즉시거부
- 비고: 확정 후 EF DB업데이트가 발생해도 보고서발행 시점 스냅샷으로 수치 재현가능. 봉인 이후 오류발견 시 일반사용자 수정불가, 관리자 개입 필요
